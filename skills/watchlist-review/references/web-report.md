# 本地网页报告

## 默认展示规范

默认产出图形化决策页，文字证据逐层展开。主页面依次展示流程状态和一句行动摘要、建议分组、持仓/现金分布、与判断相关的财务比较、后续事件时间线、逐项建议及证据。首屏须能看出是否完整、最需要关注什么；不能把长文换成大量文字卡片就称为图形化。

| 需要表达 | 默认形式 | 必须标注 |
| --- | --- | --- |
| 研究优先级 | 建议分组与可点击标的标签 | 分组为研究判断，不是量化风险评分或交易指令 |
| 仓位、集中度、现金 | 环形图配逐项金额/比例图例；项目多时用排序条形图 | 账户/市场、币种、分母、快照时间、行情是否同步；未知现金不填0 |
| 现金流和资本投入等可比事实 | 同尺度并列条形图；负数须有零轴或明确采用其他适合的图形 | 报告期、单位、来源、指标定义；不能把简单差额标成标准自由现金流 |
| 后续验证事件 | 日期时间线 | 已确认日期与预计/待定日期分开；附公告来源 |
| 单只证券的判断依据 | 简短结论卡 + 原生展开详情 | 事实、支持、反证、条件、缺口和来源都必须保留 |

图表由可追溯的结构化数据生成，不从自由文本猜金额、日期或风险等级。缺失项展示“待核实/未提供”；不画虚构收益曲线、回撤、目标价、胜率、雷达图或主观打分。没有同一时点汇率，不把不同币种画进同一个资产分布图。比较图使用同尺度，色彩同时配文字/数值，不能只靠红绿区分含义。

默认本地离线 HTML，优先 SVG/CSS 与原生展开控件，不为图表引入在线服务或外部脚本。宽屏和375px窄屏均须可读：图例不断字重叠、金额可见、页面不横向溢出；宽表允许在自身区域滚动。检查分组覆盖、金额比例合计、来源可展开和“部分完成”状态没有被图形掩盖。图形不足以说明的限制用简短文字保留。

## 数据与渲染

每次仍保留 `report.md` 便于下次对比，同时写 `report.json` 并用 `scripts/render_report.py` 生成同目录 `report.html`。HTML 不依赖第三方脚本、字体或在线服务，直接双击即可查看；来源链接仅在点击时访问。

JSON 顶层字段：

- `title`、`subtitle`、`as_of`、`generated_at`：字符串；清楚区分公告截止、生成时间与行情时间。
- `status`：`complete` 或 `partial`。Gemini 没完成时不能标完整；资料缺口保留在正文。
- `expected_symbols`：本次全部研究代码列表，渲染时核对遗漏和重复。
- `decision`：一句行动摘要；`summary`：最多三个理由字符串。
- `securities`：逐只研究对象，字段如下。
- `portfolio`、`audit`：数组，各项只有 `title`、`text`，均为纯文本。组合含真实持仓时仅本地；audit 必须有行情时刻、Gemini 状态、核验修正、未查项。
- `footer`：使用限制与下次复核方式。
- `visuals`：图表数据，格式见下。没有依据时省略对应图表并在正文说明，不为满足版式编数。

`securities` 每项的纯文本字段：`symbol`、`name`、`market`、`action`、`quote`（价格/币种/日期及延迟）、`change`、`evidence_status`、`judgment`、`facts`、`support`、`risk`、`condition`、`next_review`、`gap`。

每项另有 `sources` 数组，元素为 `{"title":"原始公告及日期","url":"https://..."}`。使用具体公告或官方页面，不用搜索结果页。没有已核验事实时明确待核实，不因格式齐全而填造数据。不要在任何字段嵌 HTML。

每项 `review_group` 为 `priority`（优先复核）、`wait`（等待验证）或 `hold`（持有观察）；由 Agent 根据本次结论填写，与 `action` 一致。不得由盈亏或关键词自动推导。

`visuals` 可包含：

- `allocations`：每组含 `title`、`currency`、`basis`（分母含义）、`as_of`、`note`、`items:[{"label":"名称","value":数值}]`。一组仅一个币种和同一快照口径；渲染器按组内项目合计归一化，金额必须有限、非负、合计大于0。不完整持仓只能标为可见明细，未知/缺失金额不传入。
- `cashflow`：含 `period`、`unit`、`source`、`note`、`items:[{"label":"名称","operating":数值,"capex":数值}]`。当前并列图仅支持非负输入；出现负经营现金流时保留文字与原值，改用有零轴的图形后再呈现，不能取绝对值或置零。差额仅为 `operating - capex`。
- `events`：`[{"date":"已核实日期或明确预计窗口","label":"事件","detail":"观察点","source":{"title":"原始来源","url":"https://..."}}]`。按实际日期排序，待定窗口单列在后，不由渲染器解析日期猜顺序。

渲染后用浏览器检查行动摘要、全量清单、展开来源及窄屏可读性。首次报告写“首次基线”，后续报告需解释相对上次改变的证据。渲染器只按给定组内金额计算图示占比，不读取券商、不生成建议，也不会自动更新 `latest-review.json`；研究完成后由 Agent 按主技能记录状态。
